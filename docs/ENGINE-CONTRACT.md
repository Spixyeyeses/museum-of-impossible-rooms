# Shared simulation contract

ES modules, array vectors `[x,y,z]`, no browser dependency. Rooms use local coordinates with bounds `{min:[...],max:[...]}` (normally y=0 floor), `spawn:{p:[...],forward:[...],up:[0,1,0]}`, and display metadata. Positions for player are eye positions. Standard eye height 1.6 times player scale, radius .24 times scale. Portal centers are aperture centers. Normal points INTO its own room; up is the top of its aperture. Right is cross(up,normal). Source to destination flips local right and normal, preserves local up and multiplies distances by `destination.height/source.height`. Widths maintain aspect. Every portal has a unique id, room id, center, normal, up, width, height, `to` reciprocal portal id, optional `requires` condition. Authored freestanding portals are supported as planes; room-wall apertures need collision openings.

World `{rooms:[...],portals:[...],objects:[...],interactables:[...]}`. Rooms have `solids:[{id, min,max,requires?}]`. Cube objects `{id,room,p,size,home:{room,p,size},color,label}` size is full side length. Interactables `{id,room,p,radius,type,label,requires?,...}` types are handled by campaign, ray hit must be spatially valid. Conditions are declarative state keys: string means truthy in `state.flags`, arrays mean all, `{not:key}` inverse. `requires` controls availability/visibility, not narrative-only labels.

State `{version:1, player:{room,p,forward,up,velocity,scale}, objects:{[id]:...mutable clone}, flags:{}, solved:[], held:null|string, journal:[], elapsed:0}`. Methods required exported by `src/engine.mjs`: `createState(world)`, `condition(state,requires)`, `portalTransform(source,dest)` returning `{point(v),direction(v),scale}`, `crossPortal(world,state,portalId)` explicit primitive for tests, `step(world,state,input,dt)` input `{forward: -1..1,strafe:-1..1,sprint?:bool}`, `look(state,yawDelta,pitchDelta)`, `trace(world,state,{origin?,direction?,maxDistance?})` trace defaults camera and reach 2.5*scale, returns `{kind:'object'|'interactable',id,distance,room}` or null, traverses at most 4 portals and accounts for walls/solids/range; `pickUp(world,state,id)` validated against trace? allow explicit object if ray target; `drop(world,state)` collision-safe; `setGravity(world,state,up)` controlled cardinal gravity; `recover(world,state)` returns current chapter room safe spawn, held objects home, `serialize(state)`, `restore(world,string)` validates and defaults invalid data safely. Extra exports welcome. Rendering maps camera quaternion from forward/up; interpolated up is presentation only. Simulation up is cardinal after controlled gravity and transformed by portals. Room gravity normally chooses [0,1,0], with state.flags[`gravity:${room}`] storing up override if needed.

Events: state.events array ephemeral `{type,...}` queue for crossing, pickup, drop, gravity, recovery. Root will consume to support campaign and UI. Automatic simulation never solves campaign except movement/events. Logic can set flags and object positions. Simulation should not require known chamber names; root provides world.startRoom and state.checkpoint room id.

Authoring/rendering should use `world.portals`, `world.rooms`, `world.objects`, `world.interactables` arrays. Room lookup can be normalized internally. Root owns campaign data and renderer. Engine author owns engine.mjs plus core tests.
